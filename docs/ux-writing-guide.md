# UX 라이팅 가이드라인

토스 앱의 보이스톤을 적용한 문구 가이드예요. 앱 안의 모든 사용자 노출 문구(버튼, 에러 메시지, 안내 문구, 다이얼로그 등)는 아래 기준을 따라요. 새 문구를 쓰거나 기존 문구를 고칠 때 이 문서를 기준으로 판단해주세요.

## 1. 해요체

제품 안의 모든 문구는 '해요체'로 써요. 상황·맥락과 무관하게 모든 문구에 일관되게 적용해요. (`습니다`체, 반말 금지)

## 2. 능동적 말하기

최대한 능동형 문장을 써요. 수동형은 특정 상황(아래 예외 규칙 참고)에서만 써요.

- "됐어요" → "했어요"
  - 알림이 설정됐어요 X
  - 알림을 설정했어요 O
- '~었' 빼기
  - 새 비밀번호로 바뀌었어요 X
  - 새 비밀번호로 바꿨어요 O
- 동사 바꿔쓰기
  - 평균 금리가 높아졌어요 X
  - 평균 금리가 올랐어요 O

## 3. 긍정적 말하기

부정적 커뮤니케이션을 최대한 줄이고 긍정형 문장을 써요.

- "안 돼요", "없어요" (X) → "~하면 할 수 있어요" (O)
  - 보호자가 허락하기 전에는 가입할 수 없어요 X
  - 보호자가 허락해야 가입할 수 있어요 O
- "없어요" → "있어요"
  - 지금 버전에는 쓸 수 없어요 X
  - 앱을 업데이트 해주세요 O
- 혜택을 받을 수 없을 때는 혜택 대상을 안내하는 긍정형 문장으로 (서비스 자체를 못 쓴다고 오해하지 않도록)
  - 모임지원금 없이 모임 통장을 만들까요? 지금 받지 않으면 모임지원금을 받을 수 없어요 X
  - 약관에 동의하면 모임지원금을 받을 수 있어요 O
  - 계좌 개설 혜택은 받을 수 없어요 X
  - 4.5% 금리 혜택만 받을 수 있어요 O

### 다이얼로그 왼쪽 버튼은 [닫기]

다이얼로그(또는 다이얼로그에 준하는 확인/취소 두 버튼 구성) 왼쪽 버튼은 "닫기"로 통일해요. "취소"는 사용자가 하고 있는 작업 자체가 취소된다고 오해할 수 있어 쓰지 않아요.

## 4. 캐주얼한 경어

'~시겠어요?', '시나요?', '~께' 같은 과도한 경어를 쓰지 않아요. 최대한 캐주얼하고 친근한 말투를 써요.

- 동사에서 '~시' 빼기
  - 카드를 해지하시겠어요? X
  - 카드를 해지할까요? O
- '계시다' → '있다'
  - 매달 보험료 얼마씩 내고 계시나요? X
  - 매달 보험료는 얼마인가요? O
- '여쭈다' → '확인하다, 묻다'
- '께' → '에게'
- 경어를 뺐을 때 어색하면, 파악하고 싶은 정보를 '주어'로 써서 문장을 새로 써봐요.
  - 어떤 목적으로 대출받으시나요? X
  - 대출 목적이 무엇인가요?

## 5. '{명사} + {명사}' 쓰지 않기

한자어 명사를 풀어서 동사 형태로 써요. 풀어쓰기 어려우면 '{명사}가 {명사}해서' 형태로만 풀어도 더 캐주얼해져요.

- 이자 환불을 받았어요 X
- 이자를 돌려받았어요 O
- 잔액 부족으로 구매하지 못했어요 X
- 잔액이 부족해서 구매하지 못했어요 O

## 예외 규칙

### 수동형이 더 나은 경우

- **서비스 종료, 기간 만료**: 주어(종료 서비스, 기간 등)를 강조하고 '종료'/'만료'의 뉘앙스를 정확히 전달할 수 있어요. 단, 주기적으로 종료가 반복되는 제품에는 "종료돼요"를 쓰지 않아요.
- **사용자에게 미치는 영향을 알려줄 때** (연체, 해지, 적용 등): 인과관계를 명확히 설명해요 — 사용자의 행동에 따라오는 결과라는 점을 알려줄 수 있어요.
- **사용자 안심**: 정보 수집 안내 등 민감한 상황에서 사용자를 안심시킬 수 있어요.

### '되어요' (X) → '돼요' (O)

모바일 화면의 좁은 공간을 고려해 '되어요'는 모두 '돼요'로 통일해요.

### 제한적으로 '~시나요?', '~셨나요?'를 쓸 수 있는 경우

- **사용자의 맥락을 활용해서 질문할 때**: 경어로 당황스러움을 줄일 수 있어요.
- **사용자의 상황을 추정할 때**: 명확한 정보가 없어 사용자가 직접 판단하게 해야 할 때, 경어로 정중하게 질문해요.
- **사용자의 선의가 필요할 때**: 설문조사처럼 사용자의 선의를 기대해야 할 때 경어로 정중하게 질문해요.

### 부정형 문장이 더 나은 경우

사용자에게 명확하게 부정적인 내용을 알려줘야 할 때는 부정형 문장을 써도 좋아요.

- **서비스를 정책상 쓸 수 없을 때**: 상황을 명확히 인지시키고, 쓸 수 없는 이유를 함께 안내해요.
- **일부 기능만 쓸 수 없을 때**: 어떤 기능을 쓸 수 없는지 명확히 인지시키고, 사용자 선택의 결과를 명확히 안내해요.
- **사용자 안심**: 정보 수집 안내 등 민감한 상황에서 부정형이 오히려 사용자를 안심시킬 수 있어요.
